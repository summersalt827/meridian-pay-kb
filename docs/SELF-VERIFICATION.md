# 自我验证清单

> 这份清单只回答一个问题：**README 里写的每一句话，别人能不能自己证明一遍？**
> 不列功能，只列可复现的检查。所有数字为本机实测（2026-10-16，本地 `main` = `5ac9495`）。
> 分数与概率是我的判断，不属于本清单的验证对象 —— 这里只验「可验证的那部分」。

---

## 0 · 一条命令（15 秒）

```bash
python3 scripts/verify.py            # 37 项快检，退出码 0 = 全通过
python3 scripts/verify.py --full     # 再跑十套测试（约 2 分钟）
```

`scripts/verify.py` 与十套测试的分工：

| | 盯什么 | 失败意味着 |
|---|---|---|
| 十套测试 | 实现是否正确 | 代码坏了 |
| `verify.py` | **文档声明是否还成立** | 话说早了 / 数字漂移了 / 产物与 README 不是同一套 |

两者会各自漂移：改了语料，相关性门余量就变；改了行业画像，邮件里的数字就变。测试全绿不代表 README 还诚实，所以需要第二只眼睛。

## 4 · 我主动标红的（清单里故意保留的失败项）

自我验证之所以可信，是因为它也记录了**没做到**的部分。以下五条不是缺陷清单，是边界声明：

| # | 边界 | 现状 | 为什么现在不补 |
|---|---|---|---|
| 1 | 赛题 #2 权限感知检索 | ⚠️ **部分** | 过滤机制已实现并测到 leak=0，但连接器是**插槽**，未在真实平台权限模型上端到端验证。语料带 `·demo` 标记，API 返回 `demo_corpus: true` |
| 2 | 赛题 #5 实时权限变更 | ⚠️ **部分** | **角色**变更即时生效（旧令牌立即 401）；**文档级**权限变更依赖 resync 窗口，无每查询回源校验 |
| 3 | 语料真实性 | 16 篇本地 Markdown | 见 `DECISIONS.md` D5：插槽设计 + 主动标注，比写「已接入」更诚实 |
| 4 | 线上冷启动 | 免费层休眠后曾实测 22.9s | 部署层限制，靠提交当天保活（`bd2983e` 的 60 分钟新鲜度窗口兜不住首屏） |
| 5 | 演示视频 | **未录** | 唯一还没拿的 bonus 分项；脚本已写好（`requirements-map.md` 8 beats），照 `?demo=1` 六步录即可 |

## 6 · 本次自验证抓到的漂移（已修）

跑第一遍 `verify.py` 时发现 README 里两个数字已经和实测对不上，已同步：

| 位置 | 原写 | 实测 | 处理 |
|---|---|---|---|
| README 评测表 | 余量 1.14x / 1.45x | **1.12x / 1.52x** | 改为实测值 |
| README 检索段 | 无关 ≤0.145 / 有答案 ≥0.244 | **0.1521 / 0.2580** | 改为实测值 |

这类漂移就是本清单存在的理由：语料一动，标定数字就动，而 README 不会自己更新。以后每次改语料后，跑一次 `verify.py` 即可确认所有对外数字仍然成立。
